Hive

Your coding agents should agree before they break each other.

Hive sits between several Claude Code agents working on one TypeScript repository. It sees what each one is changing, spots when one change reaches code another agent depends on, and gets them to sign an agreement before the edit lands.

The problem

Two agents. Two files. One silent bug.

A pricing agent switches prices to integer cents. A receipt agent, working at the same time, still treats prices as dollars. Neither did anything wrong on its own.

Why it slips through

Every usual safety check says yes.

Different files, so git is happy

The two agents never touched the same lines. A merge goes through cleanly.

A number is a number

Dollars and cents are both number to TypeScript. The compiler has nothing to complain about.

Agents can't hear each other

Each Claude Code session only knows its own task. Nobody tells the receipt agent that prices changed.

An idle agent can't be woken up

Even if you want to warn the other agent, there's no way to push a message into a session that is waiting for its developer.

How Hive works

Every agent's work moves through six visible steps.

These are the same steps you see on each agent's card in the Hive dashboard. "Agreed" and "verified" are separate steps, because a promise isn't proof.

  1. Registered

    The agent connects to Hive through Claude Code hooks and MCP.

  2. Intent

    It declares its task, its files and its assumptions, like getPrice:unit = dollars.

  3. Working

    Hive checks each edit against the compiler index and other agents' work.

  4. Agreement

    A change that reaches someone else becomes a Ghost Contract that they sign or reject.

  5. Implemented

    The real code matches the agreed declaration.

  6. Verified

    Tests ran, with exit code, source hashes and revision on record.

Ghost Contract

A promise about an interface, signed before the edit lands.

When Agent A proposes a new getPrice, Hive decides for each other agent whether it needs to be asked.

Hive signs for youYour files get no new type errors, and you stated no assumption about the changed file.
Your agent is askedYour code breaks, or you said something about this code, such as "getPrice returns dollars".

Until every agent that's asked has signed, Agent A's edit pauses and waits for your approval.

Muse Spark by Meta

The compiler can't tell dollars from cents. Muse Spark can.

Hive sends Meta's Muse Spark model what each agent said it is doing, what it assumes, and the real declarations from the code. Muse Spark explains the conflict in plain words and suggests a fix, citing that evidence. Hive validates the answer before recording it.

Muse Spark getsAgent intents and assumptions, compiler findings, and real code excerpts, with a hash of the input so stale answers are rejected.
Hive keepsOnly findings that cite real assumptions or code. The model proposes; deterministic code decides.

What's under the hood

The model proposes. Code decides.

Deterministic checks

Conflicts come from the TypeScript compiler index and type-checking each proposed edit. No guessing.

Nothing runs blindly

Hive never executes a shell command or declaration that a model suggested.

Proof, not promises

"Verified" needs a test command, its exit code, source hashes and the revision it ran on.

Meaning needs a statement

Dollars versus cents is caught from the assumptions agents state, and Muse Spark checks the meaning across them. Without a key, Hive says so instead of claiming "no conflict".

Next step, not instantly

An idle agent sees the request the next time it does anything, because Claude Code sessions can't be woken from outside.
